# AI in development

How AI was used to build this app, and where it had to be corrected. **No invented time savings.** If something was not measured, it says so.

## The workflow

1. **Rules in the repo.** [AGENTS.md](AGENTS.md) holds the code rules (strict types, tokens only, shared types, state boundaries). [CLAUDE.md](CLAUDE.md) loads them into every Claude Code session.
2. **Spec before code.** Each component has a spec in [docs/specs/components/](docs/specs/components/). AI implements from the spec, not from a vague prompt.
3. **Skills for repeatable work** (`.claude/skills/`):
   - `/new-component`: spec → component → showcase → E2E assertion → verify
   - `/verify`: typecheck, lint, E2E, tests, reported as pass / fail / skipped
   - `/adr`: record a decision
4. **Machine checks, not trust.** Lint rejects color literals and inline styles, strict TypeScript rejects missing theme keys, and a post-edit hook runs the typecheck. AI output has to pass the same gate as hand-written code.

The same pattern (canonical rules + skills + a verify gate) comes from a separate research repo where AI agents follow strict evidence rules.

## Tools

Built with a combination of Cursor, Claude (Opus and Sonnet), and Codex (Sol). The rules, specs, and gate above are the same for all of them: none of them gets a lower bar than hand-written code. Entries below say what was done, not which tool did it, because that was not tracked per change.

## Challenges and learnings

**Accessibility state doesn't reach the web.** The theme radio chips used `accessibilityState={{ selected }}`. react-native-web maps `accessibilityRole` to `role`, but ignored the state, so the chips had no `aria-checked`. `checked` (the right state for a radio) also didn't come through. The Playwright spec caught it. What worked: React Native's `aria-checked` prop, which works on native and web. Learning: prefer the `aria-*` props for state; test accessibility attributes in E2E, not just visuals.

**Typed routes break on Windows while the dev server runs.** After new files in `src/features/`, `tsc` failed: the generated `router.d.ts` listed routes like `/../features/shell/navItems`. Traced it into `@expo/router-server`: the watcher checks `path.relative(appRoot, file).startsWith('../')`, but on Windows the path starts with `..\`, so files outside `src/app` count as routes. What worked: `scripts/typed-routes.mjs` regenerates the file from `src/app` on disk, and `npm run typecheck` (and the post-edit hook) run it first. Worth an upstream issue. Learning: when a generated file is wrong, read the generator before blaming the code.

**Shadows got simpler than planned.** The first token plan had separate iOS shadow props and Android `elevation`. RN 0.76+ on the New Architecture (SDK 57 is New-Architecture only) and react-native-web both accept a CSS `boxShadow` string, so the Style Dictionary transform emits one string for every platform. Checked in the installed RN types and react-native-web source before switching.

**Slow dev servers look like test failures.** Playwright timed out on every test once because a dev server left running for days served the page but hung on the bundle request. Restarting it fixed that. With many dev servers running, bundle builds took 100 s+ against a 30 s test timeout, so the suite runs with a 90 s timeout and four workers.

**The E2E suite was testing another project.** Playwright reuses whatever is serving its port (then 8081). A dev server for a different project held that port, so specs ran against that project's code, not this one, and a layout change did not show up in the browser tests. Checking which process owned the port (`Get-NetTCPConnection` plus the process command line) found it. What worked: run this repo's server on its own port and point Playwright at it. The config now uses 8181 (2026-09-29), after the same thing failed 70 of 78 specs in a pre-release review. Learning: when a change "doesn't show up," check what is actually serving before debugging the change. A stale or wrong server is also the likely reason the iPhone did not show updates at one point, but that was not confirmed.

**Edit scripts can write the wrong line endings.** A scripted edit wrote CRLF endings and failed lint, and another added JSX before its import so Fast Refresh loaded a half-edited file. Learning: normalize line endings after scripted edits and reload after them.
